## 공부하는 방식

- **기초와 실습 병행:** 새 개념은 반드시 코드·디버깅·실험으로 검증한다.
- **매주 결과물:** 실행 가능한 소스와 짧은 README 또는 실험 기록을 남긴다.
- **매월 시연:** 작더라도 직접 플레이하거나 실행할 수 있는 결과물을 만든다.
- **주간 계획:** 1년 목표는 유지하되 상세 TODO는 최근 4주만 확정하고 주간 회고로 조정한다.
- **진척 판단:** 공부 시간과 책 페이지 수보다 빌드·테스트·설명 가능한 결과를 우선한다.

## 포트폴리오 증거

모든 실습·프로젝트는 **문제 → 가설 → 구현 → 검증 → 결과 → 게임 적용**의 형태로 기록한다. 실측 데이터가 없는 성능 향상은 주장하지 않는다. 공개 저장소이므로 개인정보 및 회사의 비공개 코드를 올리지 않는다.
